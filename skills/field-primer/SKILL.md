# 领域助读（Field Primer）

## 这件事的目的

用户是一位经济金融方向的博士生。他想在**一周内**对一个新领域建立起可用的理解——
不是背下几个名词，而是能说清这个领域在争什么、用什么办法争、现在争到哪儿了。

所以这不是「推荐阅读清单」。清单谁都会列。**你要交付的是一条路线**：
先读哪篇、为什么先读它、读完该带着什么问题去读下一篇。

## 输入

运行 `python3 scripts/primer.py --plan` 会输出一个 JSON，里面有：

- `fields`：用户设定的领域（可能不止一个），以及每个领域已经读过哪些文献（避免重复推荐）
- `keywords`：用户的研究关键词
- `existing`：读文献库里已有的题目（不要再推荐这些）
- `week`：本周的周次

## 你要产出什么

对**一个**领域（如果有多个，挑用户标了 `active: true` 的那个；都没标就挑第一个），
产出 **4–6 篇** 论文的助读，写进 `data/_claude/outbox/primer-<week>-<field>.md`，格式如下：

```markdown
# 领域助读 · <领域名> · <周次>

## 这个领域在争什么

（三到五句话。说清核心张力：哪两种解释在竞争，为什么这件事重要。
不要写教科书式的定义，要写「如果这一派对了，那么什么会不一样」。）

## 路线

### 1. <作者 (年份), 标题>
- **为什么先读它**：一句话。
- **它想回答的问题**：用中文说清楚，不要照抄摘要。
- **它怎么做的**：识别策略/数据/关键假设，说人话。
- **结论与它的边界**：结论是什么，以及在什么条件下不成立。
- **读完带着这个问题去看下一篇**：一句具体的问题。

### 2. …（同样五段）

## 一周怎么排

（给一个五天的安排：哪天读哪篇、每天大概多久、周末做什么整合。要具体。）

## 读完之后你应该能回答

（三到五个问题。能答上来就说明真的懂了。）
```

## 硬要求

- **不许编造文献**。只写你确实知道的、真实存在的论文。作者、年份、发表期刊要对得上。
  拿不准某篇是不是真的，就不要写它——宁可少一篇。
- 优先选**公认的经典**（被引量大、教科书和综述里反复出现的那些），
  而不是最近三年的新论文。用户要的是地基，不是前沿快报。
- 每篇的「怎么做的」必须写到具体：是用了什么变异、什么工具变量、什么自然实验，
  而不是「使用了面板数据方法」这种废话。
- 用中文写，但论文标题、作者名、专业术语保留英文原文。
- 已经在 `existing` 里的论文不要重复推荐。

## 收尾

写完之后：

1. 把这几篇论文用 `python3 scripts/primer.py --add <文件路径>` 写进读文献库
   （状态为「待读」，并标上 `topic` = 领域名、`primer_week` = 周次，
   这样它们会自动出现在用户的阅读队列和关卡进度里）。
2. 在 `data/_claude/inbox.md` 末尾追加一行，告诉用户这周的助读已经好了、放在哪儿。

不要推送、不要发消息——用户打开工作台就会在「AI 新产出」里看到。
