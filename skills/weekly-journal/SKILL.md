# 周报与手帐

## 分工原则（重要）

**版式、统计、图表、时间线全部由 `scripts/journal.py` 用算法生成**——它不需要你，也不该花你的额度。
你只负责三段**叙述**，因为那是算法写不出来的：

1. `上周你做了什么` —— 不是罗列，是提炼出一条主线。哪件事推进了？哪件事卡住了？
2. `本周关键` —— 最多三条，按「不做会怎样」排序，每条要给出具体的第一步。
3. `我注意到` —— 一个数据里看得见、但用户自己可能没意识到的事实。例如某刊已超过他的历史均值、
   某个关卡停了两周、运动量连续下滑、某条速记反复出现说明他心里一直挂着这件事。

## 步骤

1. 运行 `python3 scripts/journal.py --week` ，它会输出一个 JSON：上周的全部事实与统计。
2. **只读这个 JSON**，不要自己去翻数据文件（避免重复劳动和 token 浪费）。
3. 写出上面三段，字数各控制在 3–5 句。**不要用项目符号堆砌**，用完整句子。
4. 把三段以 JSON 形式写进 `data/_claude/journal-narrative.json`：
   `{"did": "...", "key": "...", "noticed": "...", "week": "2026-W31"}`
5. 运行 `python3 scripts/journal.py --render` ，它会把叙述与统计合成 `data/reports/weekly-<week>.md`
   和手帐页面 `local/journal/<week>.html`，并按配置推送到钉钉。

## 手帐的风格

手帐不是报表。它应该像一页翻开的本子：有当周的箴言、有一条走过的时间线、有几个大字号的数字、
有关卡进度的圆环、有一句你写的话。颜色克制，一页看完。**不要塞满**——留白是手帐的一部分。

## 三条不可违反

- 不编数字。所有统计只能来自 `journal.py` 的输出。
- 不夸大。这周没干什么就说没干什么，用户需要的是镜子不是彩虹屁。
- 不超过一页。手帐超过一屏就没人看了。
