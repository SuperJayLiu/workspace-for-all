# GitHub / 文献雷达

## 输入

`python3 scripts/radar.py --fetch` 会按用户设置的关键词抓回候选，输出 JSON 到
`data/_claude/radar-raw.json`（仓库：名称/描述/星标/语言/最近更新/话题；论文：标题/摘要/作者/日期/链接）。
**抓取不用你做**，GitHub 与 arXiv 的公开接口免费且确定性。

## 你要做的：判断有用没用

对照用户当前的稿件（`data/manuscripts/`）与阅读关卡（`data/levels/`），从候选里挑出**最多 5 个仓库、3 篇论文**。

**什么算有用：**
- 能直接复现或替代他正在用的方法的实现（计量估计量、结构估计、标准误修正）
- 他领域的数据管道与清洗代码（WRDS、CRSP、Compustat、CSMAR、高频数据）
- 能省掉他重复劳动的工具（表格输出、图表模板、论文工程化）
- 与他某篇在写的稿子直接相关的新证据或新识别策略

**什么不算：**
- 泛泛的 awesome-list、教程合集、课程笔记
- 星标很高但和他领域无关的通用工具
- 已经在他阅读清单里的东西（先比对 `data/reading/`）

## 输出

写进 `data/reports/radar-YYYY-MM-DD.md`，每条给出：**名称与链接 / 一句话它是什么 / 为什么对你有用（要具体到他哪篇稿子或哪个关卡）/ 上手成本**。
按「对他现在手上的活儿的相关度」排序，不按星标排序。

宁缺毋滥：这周没有真正有用的，就说「本周无值得看的」，并说明扫了多少候选。
这比凑满五条有价值得多。
