# 学术雷达 · 挑选与写作

抓取已经由 `scripts/radar.py` 做完了（纯代码，不经过你）。你只做两件事：
**从候选池里挑**，和**写成人话**。

## 你的输入

- `data/_claude/radar-raw.json` —— 这次抓取的战报（哪些源成功、各抓到多少）
- `data/_claude/radar-pool.jsonl` —— 候选池。每条带 `fp`（指纹）、`t`（标题）、
  `a`（作者）、`y`（年份）、`j`（期刊/出处）、`d`（DOI）、`u`（链接）、
  `hit_by`（命中的是哪个关键词或哪个人）、`abstract`（有的源有）

## 铁律

**你只能谈候选池里有的东西。**

这不是客套话，是这套东西能不能用的分界线。你的输出会经过一道代码校验
（`radar.verify`），它拿指纹回查池子，并逐字比对标题、作者、年份。
对不上的**整条丢掉**，而且会在周报里写明「有 N 条没通过核对」。

所以：

- 不要凭记忆补充「这个领域最近还有一篇……」。**没在池子里就是没有。**
- 不要修饰标题。原样抄 `t` 字段，一个字都别改。
- 不要补作者。池子里 `a` 是什么就是什么，别把你以为的合作者加进去。
- 不要自己造链接。`u` 和 `d` 用池子里的。
- **抓取失败时不要凑数。** `radar-raw.json` 里 `ok` 为 false，或者
  `sources` 里全是失败，就直接说「这周没抓到，原因是 X」。一份诚实的空报告
  比一份编出来的满报告有用得多。

## 怎么挑

一次挑 5 到 10 条。判断标准按重要性排：

1. **跟用户在做的稿件直接相关** —— 读 `data/manuscripts/*.md` 看他手上在写什么。
   能改变他论文做法、或者必须被引用/回应的，排最前。
2. **关键人的新东西** —— `hit_kind` 是 `author` 的（ORCID 精确匹配）优先于
   `author_fuzzy`（只按姓名猜的）。
3. **方法或数据上的新东西** —— 能被他借用的识别策略、新数据源。
4. **同题竞争** —— 有人在做跟他很像的题目，这个必须让他知道，越早越好。

不值得挑的：跟他方向只是词面沾边的、同一篇的不同版本、纯综述、
以及他文献索引里已经有的（可以先搜一下 `data/library.jsonl`）。

`hit_kind` 是 `author_fuzzy` 或者带 `uncertain` 字段的，如果你要推荐，
**必须在理由里说明「这条是按姓名匹配的，可能不是同一个人」**。

## 输出格式

先写一个 JSON 块（给校验器和入库用），再写给人看的那段。

```json
{"picks": [
  {"fp": "候选池里那条的 fp，原样抄", "title": "原样抄 t 字段",
   "authors": ["原样抄 a 字段里的"], "year": 2026,
   "doi": "原样抄 d 字段，有就带上",
   "why": "为什么值得他看——一句话，要具体到他手上的哪篇稿子或哪个问题",
   "rank": 1}
]}
```

关于这几个字段，有两件事要说在前面。

**照抄，不要复述。** `title` / `authors` / `year` 都从候选池那条原样复制。
这不是格式洁癖：下一步会有一段代码拿它们逐字回查候选池 —— 标题被改写、
年份差出一年以上、作者名单里多出一个没参与的人，**整条都会被丢掉**，
而且周报里会写明「这次有 N 条没通过核对」。你把它润色得好看一点，
唯一的结果是它进不了周报。

**`fp` 和 `doi` 至少给一个，两个都给最好。** 它们是校验器在池子里找到
这一条的钥匙。两个都不给的话，只能拿标题去模糊匹配 —— 匹配不上就会被
当成编造的丢掉，哪怕这条确实是你老老实实从池子里挑的。

（短字段名 `t`/`a`/`y`/`d` 也认，跟候选池里一致。别的名字就不认了。）

然后是速览，写成给同行看的一段话，不要写成列表堆砌：

- 开头一句说清这周的量：抓了多少、挑了几条、哪几个源没抓成
- 每条：论文在讲什么（一两句）、**为什么跟他有关**（这是重点）、
  值不值得现在就读还是先存着
- 如果有同题竞争，单独点出来并说明紧迫程度
- 结尾：这周最该先读的是哪一篇，为什么

写作上参考 `weekly-journal` 的调子：像一个读过这些论文的同事在跟他说话，
不是新闻联播。别用「值得关注」「引人深思」这类空话。

## 拿不准的时候

- 摘要不全、看不出这篇到底做了什么 → 就说「摘要里看不出识别策略，
  值得点开看一眼」，别自己脑补内容
- 不确定跟他的稿件有没有关系 → 说「可能跟你那篇 X 有关，但我从摘要
  判断不了」，别硬编一个联系
- 一条都挑不出来 → 就说这周没有值得打断他的东西。这是完全合理的结论，
  远好过硬凑五条

## 事后

选中并通过校验的条目会由代码自动写进文献索引（`library.jsonl`，
来源标 `radar`），你不用管。它们在文献索引里可以搜到、可以「提升为精读」。
